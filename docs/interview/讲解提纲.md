## 每页最关键的一句话

1. **封面**：它把模型输出变成一张带证据、可复核的风险清单。
2. **定位**：窄场景不是限制，是让规则、法条、评测和交互能一起做深。
3. **闭环**：风险清单不是终点，导出门禁和修订稿才是交付。
4. **架构**：模型被放在 API、任务存储、租约 Worker 和持久化图的中间，不是直接暴露给前端。
5. **编排**：三个 Agent 和规则引擎在同一超步；HITL 是真暂停，不是前端状态。
6. **RAG**：检索质量是一层，引用/证据门禁是另一层；后者才是防幻觉的底线。
7. **可信分层**：已核实层 P 100%，模型建议层 P 7.1%——这两层不能混；模型建议不阻断导出但必须披露。
8. **交付**：已采纳建议能落成 DOCX 修订稿和逐条变更清单。
9. **工程化**：单机也要做到任务不丢、状态可恢复、数据边界清晰。
10. **评测**：规则基线接近满分是合成数据构造使然；full 的 precision 64.9% 和 27 个误报必须一起讲。
11. **取舍**：SQLite 租约 Worker 不是高吞吐队列；先闭环，规模上来再换。
12. **复盘**：难的不是调用模型，是让输出可信、让状态可恢复、让结果可交付。
13. **Demo**：60 秒看完从选合同、并行审查、逐条复核，到修订稿和报告预览。
14. **收尾**：演示能跑只是起点；被信任、被复核、被交付才是 AI 应用工程。

## 面试官可能追问（按页）

### Q1：为什么规则基线 P 100%，full 却只有 64.9%？

规则基线只覆盖 48 个规则可检出点，8 份合成合同又和规则一起构造，所以接近满分是**构造使然**。full 模式多召回 2 个语义点，但 LLM 多带来 27 个误报，全部来自模型，没有纯规则误报。关键设计是：不把 27 个误报从评测里删掉，而是按来源和置信分层披露；已核实层 P 100%，模型建议层 P 7.1%。

### Q2：为什么不直接相信模型的自评分？

模型无法可靠判断自己是否幻觉。系统只信三个可验证状态：规则是否**真的命中**、证据能否在条款中**逐字定位**、法条 ID 是否在**本轮检索集**里。这是三档流程状态，不是概率校准。

### Q3：为什么 HITL 只拦“已核实高风险”？

因为模型建议层有 7.1% 的 precision，27 个误报如果全部阻断，演示和实际流程都会被卡死；但系统在界面和报告里明确标注模型建议，不把它混进已核实层。导出门禁只拦已核实高风险，是产品边界，不是技术遗漏。

### Q4：为什么不用 Redis / Celery / 向量数据库？

目标是单机可部署、可演示、可维护。SQLite JobStore + DB 租约 Worker 已经能做到多进程安全领取、心跳续租、崩溃回收；57 条知识库文档用 numpy 精确检索足够。规模上来后替换为外部队列 / FAISS / pgvector，接口边界已经留好。

### Q5：LangGraph 的价值是什么？不用行不行？

它提供状态图、并行超步、节点级可测、interrupt/checkpoint。不用也能串起来，但“真正并行”“暂停后恢复”“节点级单测”会变成自己维护的胶水。代价是学习曲线和 checkpointer 生命周期成本，这在取舍页写出来了。

### Q6：HITL 的暂停是怎么跨重启的？

`human_review` 节点在 `gate` 后 `interrupt`，图状态由 `AsyncSqliteSaver` 写入独立的 `checkpoints.sqlite3`。用户决策后 `Command(resume=...)` 从暂停点继续；暂停任务跨后端重启仍可恢复。`running` 崩溃不自动重放 LLM，避免重复计费。

### Q7：怎么防止模型编法条 / 编原文？

三道硬门禁：Pydantic schema、证据逐字子串、法条 ID 必须在检索上下文；法条正文由后端从知识库渲染，模型不能生成法条原文。第四道是人工复核。合同被当作 untrusted input，prompt 明确要求忽略合同中的指令性文字。

### Q8：真实数据效果怎么样？

目前只有 3 份真实 PDF、1 份 in-scope，作者单人标注，无 IAA，不能声称真实泛化或法务准确率。下一阶段是 20–30 份真实合同、双人盲标、IAA、holdout，再谈外部效度。现有 8 份合成合同和 51 个标注点只用于回归和能力边界诊断。

### Q9：成本 / 延迟能接受吗？

8 份合同 full 模式共 48 次 LLM 调用，输入 110,971 / 输出 37,532 tokens，按假设单价估算 ¥0.1638，约 ¥0.0205/份；mean 77.4s，p95 92.6s。实际账单、embedding/rerank 未计入，汇报时必须说“估算”。

### Q10：如果给你更多时间，先做什么？

优先级：真实数据可信度 > 生产隔离 > 能力扩展。先补 20–30 份双人盲标 + IAA + holdout；再做多租户/RBAC/TLS、对象存储、外部队列；最后才是更多合同类型和版面结构化 OCR。

## 口径提醒（不要在面试中过度表述）

- 说“8 份合成合同 + 51 个标注点”，不要说“真实 benchmark”。
- 说“证据定位率 100%”，它的分母是提供了原文引用的风险，不等于分析质量 100%。
- 说“法条 ID 可解析率 100%”，它只衡量 ID 是否存在于知识库，不等于法条相关性准确率。
- 说“full P 64.9%”，必须同时说“已核实层 P 100%、模型建议层 P 7.1%”。
- 说“约 ¥0.0205/份”，必须加“按假设单价估算，不含 embedding/rerank/重试”。
- 说“实时评测 live 结果”，注明日期 2026-11-02；mock 截图不等于 live 模型效果。
